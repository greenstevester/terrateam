# CLAUDE.md - Backend (OCaml)

This file provides guidance for Claude Code when working with the OCaml backend components of Terrateam.

## Overview

The Terrateam backend is a sophisticated OCaml application built with:
- **193+ OCaml modules** organized by functional domains
- **Custom ABB framework** for high-performance async operations
- **PDS build system** for modular compilation and dependency management
- **Type-safe API layer** with OpenAPI-generated bindings

## Architecture

### Core Application Structure

**Primary Executables:**
- `terrat_oss` - Open source Terrateam server
- `terrat_ee` - Enterprise edition server  
- `iris` - Frontend web application (Svelte-based)

**Major Framework Components:**

#### ABB Framework (Application Building Blocks)
High-performance async runtime and utilities:
- `abb` - Core async runtime with platform-specific schedulers
- `abb_future_combinators` - Functional async programming primitives
- `abb_io` - Async I/O operations
- `abb_curl` - HTTP client with connection pooling
- `abb_tcp_server` - TCP server framework
- `abb_tls` - TLS/SSL support
- `abb_process` - Process management
- `abb_cache` - Caching layer with LRU eviction

#### BRTL Framework (Web Framework)
Web server and request handling:
- `brtl` - Core web framework
- `brtl_mw_session` - Session middleware
- `brtl_mw_log` - Logging middleware
- `brtl_static` - Static file serving
- `brtl_pagination` - Pagination utilities

### Domain-Specific Modules

#### Core Terrateam Logic
- `terrat` - Main application logic
- `terrat_config` - Configuration management
- `terrat_data` - Data access layer
- `terrat_storage` - Persistent storage

## Development Commands

### Building

```bash
# Load OCaml environment
eval $(opam env)

# Build all components
make all

# Build specific targets
make release-terrat    # Release binaries
make debug-terrat      # Debug binaries
make terrat-schemas    # Generate API schemas
make test-terrat       # Run tests

# Build individual components
make release_terrat_oss
make release_terrat_ee
make release_iris
```

### Code Generation

```bash
# Generate API schemas from OpenAPI specs
make terrat-api
make terrat-repo-config
make terrat-webhooks

# Generate GitHub/GitLab API clients
make github-api
make gitlab-api
```

### Testing

```bash
# Run all tests
make test-terrat

# Run specific test suites
make test-release_terrat_github_webhooks
make test-release_terrat_sql_of_tag_query
make test-debug_abb_fut
```

## Key Configuration Files

### Build System
- **`pds.conf`** - PDS package configuration with 193+ module definitions
- **`Makefile`** - Build targets and code generation rules
- **`hll.conf`** - Package metadata and dependency mapping
- **`hll.pins`** - Exact dependency versions for reproducible builds

### Runtime Configuration
- **`.ocamlformat`** - Code formatting rules
- **`dune*`** files - Generated by PDS for dune compatibility

## Development Patterns

### Module Organization
- **Domain-first**: Modules grouped by business domain (VCS, auth, workflow)
- **Layered architecture**: Clear separation between framework, domain, and application layers
- **Type safety**: Extensive use of OCaml's type system for compile-time guarantees

### Async Programming
```ocaml
(* ABB framework patterns *)
open Abb.Future.Syntax

let process_request request =
  let* validation_result = validate_request request in
  let* data = fetch_data validation_result in
  let* result = transform_data data in
  return result
```

### Error Handling
```ocaml
(* Result-based error handling *)
type ('a, 'error) result = Ok of 'a | Error of 'error

let safe_operation input =
  match validate input with
  | Error err -> Error (`Validation_error err)
  | Ok validated ->
    match process validated with
    | Error err -> Error (`Processing_error err)
    | Ok result -> Ok result
```

### Code Generation Integration
- **OpenAPI First**: All API types generated from OpenAPI specifications
- **Schema Validation**: JSON Schema validation for configurations
- **Type Consistency**: Generated types ensure consistency between frontend and backend

## Common Development Tasks

### Adding New API Endpoints
1. Update OpenAPI spec in `api_schemas/terrat/api.json`
2. Run `make terrat-api` to regenerate types
3. Implement endpoint in appropriate `terrat_*` module
4. Add tests in `tests/` directory

### Adding New VCS Provider
1. Create new modules following pattern:
   - `terrat_vcs_api_provider` - API client
   - `terrat_vcs_service_provider_oss` - OSS implementation
   - `terrat_vcs_service_provider_ee` - Enterprise implementation
2. Update `pds.conf` with module dependencies
3. Implement required VCS interface

### Performance Optimization
- **Profile with**: `perf`, `gprof`, or OCaml profiling tools
- **Memory usage**: Monitor with `ocaml-gprof` and memory profilers
- **Async performance**: Use ABB framework's built-in metrics
- **Database queries**: Optimize SQL generation in tag query system

## Debugging

### Common Issues
- **Build failures**: Usually dependency-related, check `pds.conf` and `hll.pins`
- **Runtime errors**: Use OCaml's stack traces and logging
- **Performance issues**: Profile async operations and database queries
- **Type errors**: OCaml's type system provides excellent error messages

### Logging
```ocaml
(* Structured logging with the logs library *)
open Logs.Src

let log_src = Logs.Src.create "terrateam.module_name"
module Log = (val Logs.src_log log_src : Logs.LOG)

Log.info (fun m -> m "Processing request %s" request_id);
Log.err (fun m -> m "Failed to process: %s" error_message);
```

## Architecture Decisions

### Why OCaml?
- **Type Safety**: Compile-time guarantees prevent many runtime errors
- **Performance**: Native compilation with excellent performance characteristics
- **Concurrency**: ABB framework provides high-performance async without runtime overhead
- **Ecosystem**: Rich ecosystem for web services, JSON, and system programming

### Custom ABB Framework
- **Performance**: Optimized for I/O-heavy workloads with minimal allocation
- **Platform Support**: Platform-specific optimizations (kqueue on BSD/macOS, epoll on Linux)
- **Type Safety**: Fully typed async programming model
- **Integration**: Seamless integration with OCaml ecosystem

### PDS Build System
- **Modularity**: Clean separation of 193+ modules with precise dependencies
- **Reproducibility**: Exact dependency versioning with `hll.pins`
- **Cross-compilation**: Support for multiple platforms and architectures
- **IDE Integration**: Automatic `.merlin` generation for editor support

This backend architecture provides a robust, type-safe foundation for Terrateam's infrastructure automation platform.
